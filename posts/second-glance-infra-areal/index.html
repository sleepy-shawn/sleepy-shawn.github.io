How to design a novel architecture with a novel RL algorithm.

Paper: AReaL: A Large-Scale Asynchronous Reinforcement Learning System for Language Reasoning

Challenges#

  • Switching between training and generation.
  • Unequal output lengths.

  • Inconsistent policies and stale data.
  • Synchronous systems reduce the batch size per GPU, leading to memory-I/O-bound execution and poor scalability.

System Architecture#

Interruptible rollout workers belong to the generation stage. The interrupt request is “Update Weights.”

Trainer workers accumulate data until the buffer reaches the batch size.

Rollout controller:

Read data and invoke generation → Send responses to the reward service → Store trajectories and rewards in the buffer → Update the model → Update the workers.

Equipped Algorithm#

For Staleness#

  • η represents the maximum permitted staleness in each training batch.
  • Prioritize older trajectories from the data buffer to form a training batch.
  • The rollout controller tracks both the generated samples N_r and policy version i from the parameter server.
  • Favor a large η.

In practice, use the parameters before updating as the proximal policy.

For Better RL Results#

Compared with PPO:

  • The outer importance ratio always uses the behavior policy as the denominator.
  • The key choice is the trust-region ratio using the proximal policy.

Implementation Details I Should Know#

  • CPU work: Rule-based computation and TCP-based data transfer.
  • Separate threads and pipelining: Overlap GPU generation and CPU operations.
  • Asyncio coroutines: Avoid mutually blocking waits in the rollout worker.
  • Batching: A padding-free sequence-packing strategy coupled with a dynamic allocation algorithm.

Dynamic Batching#

Instead of using a fixed batch size for sequences of different lengths, AReaL recombines sequences into batches through a greedy algorithm. Long sequences can cause OOM, while inefficient batching can underutilize memory.

Sequence Packing#

This is not this paper’s innovation. Concatenation enables padding-free execution with attention isolation.

Evaluation Designs#

  • Comprehensive comparisons against state-of-the-art open-source frameworks across model sizes.
  • Strong-scaling analysis with varying compute resources.
  • Ablation studies validating design choices.

Baseline: veRL.

Ablation: Decoupled PPO.

Insight#

Allocating 75% of resources to inference and 25% to training demonstrated higher training throughput.

My Prospect of the Future#

  • MoE architecture optimization.
  • More design work around the differences between training and generation.

Preliminaries#

Generation involves autoregressive decoding, which requires efficient KV-cache management and optimized decoding kernels.

Training requires careful orchestration of data, tensor, and pipeline parallelism strategies.

Reference#

AReaL: A Large-Scale Asynchronous Reinforcement Learning System for Language Reasoning.
