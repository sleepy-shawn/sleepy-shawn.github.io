Perplexity#

In pre-training, you minimize perplexity on the training set.

The obvious thing is to measure perplexity on the test set.

This is what people did traditionally in language modeling research.

GPT-2: Zero-shot on standard datasets (out-of-distribution evaluation)

Perplexity is all you need (more faith than science):

The true distribution is t, and the model is p.

The best possible perplexity is H(t), obtained iff p = t.

If p = t, then we can solve all the tasks: p(solution | problem).

Agent 2.0: Deep Agents, proactive architecture#

Deep agents use tools to create and maintain an explicit plan, which can be a to-do list in a Markdown document.

Between steps, the agent reviews and updates this plan, marking steps as pending, in_progress, or completed, or adding notes.

If a step fails, it doesn’t just retry blindly; it updates the plan to accommodate the failure. This keeps the agent focused on the high-level task.

A sub-agent (e.g., a “Researcher,” a “Coder,” a “Writer”) performs its tool call loops (searching, erroring, retrying), compiles the final answer, and returns only the synthesized answer to the Orchestrator.

Agents utilize external memory sources, like filesystems or vector databases, as their source of truth.

Frameworks like Claude Code and Manus give agents read/write access to them.

This shifts the paradigm from “remembering everything” to “knowing where to find information.”

Smarter models do not require less prompting; they require better context. You cannot get Agent 2.0 behavior with a prompt that says, “You are a helpful AI.” Deep Agents rely on highly detailed instructions, sometimes thousands of tokens long. These define:

  • When to stop and plan before acting.
  • Protocols for when to spawn a sub-agent vs. doing work themselves.
  • Tool definitions and examples of how and when to use them.
  • Standards for file naming and directory structures.
  • Strict formats for human-in-the-loop collaboration.

It is a shift from reactive loops to proactive architecture. It is about better engineering around the model.

The term “Deep Agents” was notably popularized by the LangChain team to describe this architectural evolution.

  • Route 2: encourage reporting norms (e.g., people report confidence intervals).
  • Route 3: use fresh evals.
  • Route 4: use private evals.
