Applications#

  • Actual use in agents and chat
  • Model evaluation
  • Reinforcement learning

Why efficiency matters: training is a one-time cost, while inference is repeated many times.

Open-source packages:

  • vLLM: PagedAttention from Berkeley
  • SGLang: RadixAttention from Berkeley, good for agentic workloads
  • TensorRT-LLM: from NVIDIA

Metrics#

  1. Time to first token (TTFT): how long the user waits before any generation happens (for interactive applications)
  2. Latency (seconds/token): how fast tokens appear for one query (for interactive applications)
  3. Throughput (tokens/second): how fast tokens appear for many queries (for batch processing)

Question: You have to generate sequentially and can’t parallelize over generation, so it’s harder to fully utilize compute.

Review of the Transformer#

Conventions:

  1. F = 4 D (the MLP up-projects to 4× the model dimension)
  2. D = N H (the model dimension is split across N heads)
  3. N = K G (for GQA, the heads are split across K groups)
  4. S = T (during training, condition on S input tokens to predict T output tokens)

Intensity analysis#

Assuming B is much less than D and F, we can simplify the intensity to B.

If computation intensity > accelerator intensity, we’re compute-bound (good).

If computation intensity < accelerator intensity, we’re memory-bound (bad).

Conclusion: compute-bound iff B > 295.

The extreme case is when the batch size is 1, which happens with inference.

After storing the KV cache in HBM:

Two stages of inference:

  1. Prefill: given a prompt, encode it into vectors (parallelizable as in training).
  2. Generation: generate new response tokens (sequential).

Unlike MLP intensity, attention intensity has no dependence on B, so batching doesn’t help!

Why?

  1. In MLP layers, every sequence hits the same MLP weights (Wup, Wgate, and Wdown don’t depend on B).
  2. In attention layers, every sequence has its own KV cache vectors (Q, K, and V all depend on B).

Summary:

  1. Prefill is compute-bound, while generation is memory-bound.
  2. Prefill MLP intensity: B × S
  3. Prefill attention intensity: S/2
  4. Generation MLP intensity: B (requires concurrent requests)
  5. Generation attention intensity: <1 (impossible to improve)

Throughput and Latency#

We know that inference is memory-bound.

Assumption: We can overlap compute and communication perfectly and ignore overhead. In this case, inference time is bound by memory and determined by memory I/O.

# Total memory usage
memory = B * kv_cache_size_per_seq + parameter_size

# Latency is determined by memory I/O
latency = memory / memory_bandwidth

# Throughput is the inverse of latency, with B tokens generated in parallel
throughput = B / latency

Result: even worse latency and even better throughput, though throughput gains diminish too…

When increasing the batch size:

  1. Latency worsens because there’s a larger KV cache (O(B) in size) to read and write.
  2. Throughput improves because batching amortizes the cost of reading parameters.

Easy parallelism: if you launch M copies of the model, latency stays the same and throughput increases by a factor of M!

Harder parallelism: shard the model and the KV cache.

Use smaller batch sizes during prefill for faster TTFT.

Use larger batch sizes during generation to improve throughput.

Multi-head latent attention (MLA)#

DeepSeek-V2: reduce N × H = 16384 to C = 512.

Wrinkle: MLA is not compatible with RoPE, so we need to add 64 dimensions for RoPE, giving 512 + 64 = 576 total dimensions.

Sliding window attention#

I remember MiMo V2.6 used it.

Idea: just look at the local context, which is most relevant for modeling.

The effective context scales linearly with the number of layers.

Problem: this can still hurt accuracy.

Solution: interleave local attention with global attention.

Quantization#

# Mechanics
x = 5.2342
scale = 0.1
zero_point = 4
x_quant = round(x / scale) + zero_point  # Quantize
x_approx = (x_quant - zero_point) * scale  # Dequantize

Post-training quantization (PTQ): Run on sample data to determine the scale and zero point for each layer or tensor.

Quantization-aware training (QAT): During training, quantize and dequantize during the forward pass to simulate quantization errors.

Other methods: activation-aware training and model pruning.

Speculative sampling#

Checking is faster than generation.

Use a cheaper draft model p to guess a few tokens.

Evaluate them with the target model q (process the tokens in parallel), and accept them if they look good.

Rejection sampling: the key property is that it guarantees an exact sample from the target model!

  1. Medusa: the draft model generates multiple tokens in parallel.
  2. EAGLE: the draft model takes high-level features from the target model.
  3. There’s lots of room for innovation on the draft model (involves training).

Continuous batching & selective batching#

Inference: requests arrive and finish at different times, so you have a ragged array.

Solution: use iteration-level scheduling to add new requests to the batch as they arrive.

Problem: continuous batching works when all sequences have the same dimensionality, but requests may have different lengths.

Solution: continuous batching.

Attention computation stays the same: process each sequence separately.

Non-attention computation: sequences can be concatenated.

Paged Attention#

Problem: fragmentation (external and internal).

Solution: paged attention, which also makes sharing easy.

Other vLLM optimizations:

  • Use a kernel to fuse block reads and attention.
  • Use the latest kernels.
  • Use CUDA graphs to avoid kernel launch overhead.
