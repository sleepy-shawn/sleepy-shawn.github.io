Paper: PrefixFlow: Training-Time KV Caching for Schedule-Level Prefix Reuse in LLM RL Training

Motivation#

There has been limited work on prefix reuse during training. The related mechanisms in SGLang and vLLM support forward passes only.

The loss may be computed only over the suffix, but gradients still flow to prefix-side parameters through attention. Repeated prefix computation is a real bottleneck.

Workloads with a high prefix ratio include RAG, multimodal tasks, and long-context QA.

During backpropagation, exchanging the order of summation and matrix multiplication yields an equivalent result.

Disadvantages of Using a Single Computation Graph#

  • Prefix and suffix computation have heterogeneous context-parallelism requirements, leaving suffix-heavy ranks on the critical path.
  • Prefix activations cannot be offloaded until the graph has finished executing.
  • Pipeline parallelism requires many microbatches, but one graph per group yields only a few.

Reducing computation does not always lead to shorter steps or lower memory usage.

Advantages of Schedule-Level Prefix Reuse#

  • Context parallelism can be balanced separately for the prefix and suffix.
  • Prefix activations can be offloaded between phases.
  • Pipeline parallelism can benefit from many microbatches.
  • Suffix forward and backward passes can be scheduled more flexibly.

Key Design#

  1. Phase A: Prefix forward.
  2. Phase B: Suffix microbatches.
  3. Phase C: Prefix backward. Inject the accumulated gK/gV cache into the retained prefix graph and run one shared prefix backward pass.

Offloading Mechanism#

PrefixFlow keeps the hot cache resident, offloads dormant tensors to a pinned host-memory pool, and asynchronously prefetches them for Phase C. It reinvests the released high-bandwidth memory (HBM) in suffix work.

These optimizations all benefit Phase B: they allow larger suffix waves, longer suffixes, and more expensive transient state to remain resident.

Note that one wave can contain multiple microbatches.

Context Parallelism#

Under context parallelism (CP), each layer must all-gather the prefix K/V for suffix attention and reduce gK/gV back to the owning prefix shards. Prefetching the all-gathered K/V across layers accelerates this process.

This case is more challenging than those addressed by existing approaches such as DeepSpeed Ulysses and Ring Attention.

In Phase B, balancing prefix and suffix work together is difficult. This is also why reusing the prefix within a single computation graph offers limited improvements.

Solution: Balance CP in Separate Stages#

  • For non-attention operators, token-wise work is balanced within a single computation mode.
  • For attention, CP algorithms can be applied independently.
  • Gather prefix K/V as read-only data, then reduce the gradients back to the owning prefix shards.

Pipeline Parallelism#

Switch phases locally within each pipeline stage. Suffix forward passes must wait for the required prefix forward computation to finish, rather than for a global phase barrier.

Expert Parallelism#

Use Rollout Routing Replay, assuming dropless MoE layers.

Implementation Details#

Framework: TorchTitan.

Phase A does not expose its live graph directly to Phase B. Instead, it creates detached cached leaves for suffix attention and registers coupling hooks on the live prefix keys and values.

Each Phase-B suffix microbatch step builds a short-lived suffix graph, calls backward without retaining the live prefix graph, and accumulates the resulting coupling gradients in the cached leaves.

Phase B is the main target for torch.compile. Phase-A capture and Phase-C delayed backward rely on autograd.

Experiment Design#

Parallelism#

  • Trajectory alignment under composed parallelism.
  • Phase-B prefetching and balancing.
  • Pipeline-parallel stage-local phase switching.

Real RL Loop#

  • End-to-end performance in terms of training quality (reward and actor loss) and efficiency. Synchronization also improves because waiting times are shorter.
  • No amplification of drift over the replayed trajectory.
  • Speedup varies with the prefix-to-suffix ratio and whether compilation is enabled.
  • Offloading dormant prefix activations creates memory headroom and enables faster suffix execution.

Future Directions#

  • Kernel-level reuse and schedule-level reuse are complementary.
  • Tree-structured RL data.
  • Long single sequences.
