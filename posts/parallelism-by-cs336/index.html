Building blocks of distributed communication#

The difference between microbatching and data parallelism is that microbatching distributes batches across the temporal dimension, while data parallelism distributes them across GPUs.

  • Rank: A particular device/GPU (e.g., 0, 1, 2, 3).
  • World size: The total number of devices (e.g., 4).

Operations:

  • Foundations: Broadcast, gather, and reduce.
  • Workhorse: All-gather (gather to all ranks).
  • Reduce-scatter reduces over dimensions and scatters the results across ranks.
  • All-reduce is reduce-scatter followed by all-gather. The order matters.
  • All-to-all for MoEs is the most general operation. Each rank sends a tensor to every other rank. With balanced splits, it looks like a transpose.
  • Scatter is the inverse of gather.

RDMA enables one GPU to directly read from or write to another GPU’s memory without involving the CPU.

InfiniBand supports RDMA. NCCL (NVIDIA Collective Communications Library) translates collective operations into low-level packets sent between GPUs.

  • Intra-node: NVSwitch and NVLink.
  • Inter-node: InfiniBand and RoCE (RDMA over Converged Ethernet).

Data parallelism in more detail#

Naive data parallelism has a memory problem.

  • FP16 weights for the forward and backward passes.
  • FP32 weights for updates.

ZeRO addresses the memory overhead of data parallelism.

Naive#

All-reduce the gradients.

Stage 1#

  • Split up the optimizer state across GPUs.
  • Each GPU has the full parameters and gradients.
  • Reduce-scatter the gradients, which incurs communication costs. Each machine then updates its parameters using the gradients and optimizer state.
  • Finally, all-gather the parameters, which incurs communication costs.
  • Key finding: ZeRO Stage 1 saves memory for free in the bandwidth-limited regime because all-reduce is equivalent to reduce-scatter followed by all-gather.

Stage 2#

  • Split up the gradients and optimizer states.
  • The complication is that we can never instantiate a full gradient vector, but each worker must compute a full gradient because we are using data parallelism.
  • Each worker goes backward through the computation graph incrementally. After computing a layer’s gradients, it immediately reduces them and sends them to the right worker.
  • Each machine updates its parameters using the gradients and optimizer state.
  • All-gather the parameters.

Stage 3#

  • Forward: Load the model shard → all-gather the parameters → run the forward pass → free the full weights.
  • Backward: All-gather the parameters → run the local backward pass → reduce-scatter → free the full weights → update the parameters.
  • Two all-gathers and one reduce-scatter.

Two important ideas#

  • Incremental computation and communication.
  • Overlapping communication and computation.

Remember that batch size is a scarce resource#

ZeRO Stage 3 is nice in principle, but it does not reduce activation memory.

Model parallelism (PP, TP, CP, and EP) splits the work across GPUs but requires them to communicate activations.

Pipeline parallelism processes microbatches#

  • Why use pipeline parallelism? It has good communication properties and only sends activations point to point.
  • Batch sizes are key to hiding the bubble.
  • “Zero-bubble” pipelining.
  • Split the backward pass into two parts: (1) backpropagating activations (z, x) and (2) computing weight gradients (W).
  • The second part can be done whenever needed.

Tensor parallelism gives each GPU a submatrix#

  • Column-wise: QKV and up-projection (no all-reduce needed).
  • Row-wise: Attention output and down-projection (all-reduce needed).
  • On GPUs, use tensor parallelism within a node (up to eight GPUs) because of the high-speed interconnects.
  • Tensor parallelism requires much more communication than pipeline parallelism.

Pipeline parallelism uses bsh point-to-point communication per microbatch.

  • b: Microbatch size.
  • s: Sequence length.
  • h: Hidden dimension.

  • Two all-reduces per layer (attention output and MLP down-projection).
  • BF16 activations use 2bsh bytes.
  • Use tensor parallelism whenever we have low-latency, high-bandwidth interconnects.

Expert parallelism#

EP advantages:

  • Better GEMM efficiency with larger local matrices, improving GPU utilization.
  • Lower communication.
  • A simpler computation graph makes it easier to overlap communication with computation.
  • Local token permutation is eliminated.

DP usually shares replicas with the EP split. DP and TP can interact poorly and lower utilization.

Decouple attention and expert parallelism.

The looped Transformer influenced FSDP.

Use high TP for attention parallelism and low TP for MLP parallelism.

Use ring attention for context parallelism.

See Megatron for more details.

Guideline 1: Minimize Model Parallelism, Maximize Data Parallelism#

Model parallelism introduces communication overhead that hurts performance.

Guideline 2: Keep EP and TP Communication Within the NVLink Domain#

EP and TP are communication-intensive. NVLink provides much higher bandwidth than cross-node interconnects.
