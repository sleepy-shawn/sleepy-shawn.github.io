Through this paper, I understand the research pipeline in infra, especially in how to design an infrastructure for a specific popular training algorithm, which serves as a solid base for me to explore more in this area. By the way, I know a few professional explanations and code organization in this process.

Paper: HybridFlow: A Flexible and Efficient RLHF Framework

Basic Knowledge#

  • DP: Data Parallelism, more model replicas.
  • TP: Tensor Parallelism, divide matrix into little matrices.
  • PP: Pipeline Parallelism, attention for one GPU and MLP for another.
  • Inference: One forward pass.
  • Generation: Multiple forward passes.
  • All-Gather: Collect data from all GPUs and each one then gets a complete copy of data.
  • Reduce-Scatter: Collect and reduce data from all GPUs and then scatter part of reduced data to each GPU.
  • Rank: Distributed process ID.

Existing Works’ Shortcomings#

Single controller avoids complex point-to-point send and receive workflows, boosting more flexibility.

Analysis of RLHF (Take PPO as an Example)#

  • Actor training: Computation bound, more TP, more PP, less DP.
  • Generation: GPU memory bound, more DP, less TP, less PP due to no gradient, no backward, no optimizer.
  • Model resharding leads to memory redundancy.

Code Realization#

APIs encapsulate distributed computation and support 3D parallelism, ZeRO, and PyTorch FSDP.

Python decorator: Additional functions without changing the code.

NCCL communication primitives collect and concatenate model parameters in each micro-DP group during the transition between training and generation.

Related Work Analysis#

  • DeepSpeed-Colocation: Actor training and generation in the same GPU, model resharding between training and generation.
  • OpenRLHF: Each model placed on separate devices, two copies of generation and training models.
  • NeMo-Aligner: Actor/Ref colocate, Critic-Reward colocate, same model for generation and training.
  • Single controller: Insufficient for large GPU distribution.
  • Multi-controller: Inflexible to implement various RLHF workflows.

Key Design#

  • Single-controller in inter-node.
  • Multi-controller in intra-node.

Hierarchical API#

  • Use resource pools to manage GPUs.
  • Configure models with different parallelism and then allocate devices.
  • Asynchronous execution using data futures.

3D-Hybrid Engine#

Workflow: Switch Between Actor Training and Generation#

Dg is determined by p, t, pg, dg.

All-gather weights → Load prompts → Generate and all-gather responses → Partition weights → Model update → All-gather weights.

Zero Memory Redundancy#

All-gather within micro-DP groups enables both efficiency and no redundancy.

Auto Mapping#

Auto parallel + simulation + double nested loop for best mapping.

Nested loop:

  1. Find best placements for actor, critic, reference, reward.
  2. Find best allocation for each group.

Experiment Design#

  1. Compare throughput across three RLHF algorithms.
  2. Compare throughput under different model placements, GPU counts, and model sizes.
  3. Compare the time of different transitions across GPU counts and model sizes.
  4. Break down actor model execution time under different parallelism strategies and model sizes.

Design Principles#

  • Flexible.
  • Efficient.
  • Simple for users.
  • Avoid a central bottleneck.

Reference#

Guangming Sheng et al. HybridFlow: A Flexible and Efficient RLHF Framework, 2024.
