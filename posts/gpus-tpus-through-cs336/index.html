These notes follow Stanford CS336, Lecture 5 on GPUs and TPUs. TFLOPS measures trillions of floating-point operations per second.

Part 1. GPU Architecture#

GPUs have many small compute units and devote less hardware to caching and control than CPUs typically do. GPUs are optimized for throughput, while CPUs are optimized for low latency.

Each streaming multiprocessor (SM) contains many streaming processors (SPs). CUDA cores perform scalar operations. Tensor Cores accelerate matrix multiplication and accumulation.

Threads, Blocks, and Warps#

  • Threads run the same kernel in parallel, typically on different inputs.
  • Blocks group threads that share a region of memory and can cooperate. Each block runs on one SM, and an SM can host multiple blocks.
  • Warps are groups of 32 consecutively numbered threads that the GPU schedules together.

Each thread can access its own registers and the shared memory of its block. Data shared across blocks generally goes through global memory, which is backed by GPU device memory and is slower to access than on-chip storage.

TPUs feature large matrix multiplication units, fast memory, and lightweight control. GPUs are also massively parallel, and the single-instruction, multiple-thread (SIMT) model makes that parallelism straightforward to program. Threads are lightweight, and adding SMs can scale workloads with enough parallel work.

Compute throughput has grown faster than memory bandwidth, so making good use of the memory hierarchy matters for performance.

Part 2. Understanding GPU Performance#

The Roofline Model#

Operational intensity is the number of floating-point operations per byte transferred. Throughput is the number of floating-point operations per second. The sloped region on the left is memory-bound. The flat region on the right is compute-bound.

Dense matrix multiplication processes all entries, including zeros. Sparse matrix multiplication can skip work associated with zero entries.

Control Divergence and Lower Precision#

Control divergence. When threads in a warp take different branches, they may have to execute the paths separately. For suitable operations, a kernel can use an execution mask to control which lanes participate.

Lower precision. Fewer bits per value means fewer bytes to move. Modern GPUs support low-precision and mixed-precision operations.

  • FP16 and BF16 can be used for matrix multiplication and pointwise operations.
  • Reductions such as sums, softmax, and normalization often use FP32 accumulation even when inputs are in FP16. Adding small values to a large sum can introduce rounding errors.
  • Dynamic range matters for operations such as powers, exponentials, and loss calculations. FP32 and BF16 offer a wider exponent range than FP16.

MXFP8 scaling factors use E8M0, with eight exponent bits and zero mantissa bits.

Operator Fusion and Recomputation#

Operator fusion combines operations in one kernel so intermediate results can stay near the compute units, reducing trips to global memory.

torch.compile can automatically fuse some straightforward operations. Recomputation discards selected activations in the forward pass and regenerates them during the backward pass to save memory.

Memory Coalescing, Tiling, and Scheduling#

Memory coalescing combines nearby accesses by threads in a warp into fewer memory transactions. In the example below, the threads’ addresses fall within one burst segment.

Tiling divides matrix multiplication into blocks so threads can reuse data. Tile sizes that do not fit the matrix dimensions and poorly aligned accesses can limit performance.

Aligning dimensions to a multiple of 32 can be faster than aligning to a multiple of 16, depending on the kernel and hardware. Grouping and ordering threads to reuse shared memory can also reduce global memory accesses.

Wave quantization occurs when the number of tiles does not line up with the available SMs, leaving some SMs idle in the last wave.

Part 3. FlashAttention#

The output projection, shown as P_mix, mixes the outputs of the attention heads. Computing all pairs of attention scores has quadratic complexity in sequence length.

FlashAttention tiles the query, key, and value computations and fuses the operations. Its incremental softmax tracks a running maximum and a running normalization sum. When a new tile changes the maximum, the previous sum and output contributions are rescaled so they remain on the same scale. Subtracting the maximum before exponentiation makes softmax numerically stable.
